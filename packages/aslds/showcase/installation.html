Framework Files

Organize the Framework Correctly

Place the ASL Design System inside a predictable project structure so that CSS, JavaScript and documentation assets remain easy to maintain as your application grows. 

project/
│
├── css/
│   ├── reset.css
│   ├── variables.css
│   ├── typography.css
│   ├── layout.css
│   ├── utilities.css
│   ├── animations.css
│   └── components/
│
├── js/
│
├── assets/
│
├── showcase/
│
├── foundations/
│
└── components/

css/

Stores the complete ASLDS framework, design tokens, utilities and reusable component stylesheets.

js/

Contains modular JavaScript files responsible for framework interactivity and component behaviour.

assets/

Keep application images, icons, fonts, videos and downloadable resources in a single location.

showcase/

Contains the official documentation website demonstrating every ASLDS feature and guideline.

foundations/

Documentation covering colors, typography, spacing, layout, borders, icons and animations.

components/

Individual documentation pages for every reusable ASL Design System component.

CSS Installation

Load Framework Styles in the Correct Order

The loading order is an essential part of the ASL Design System architecture. Core framework files must always be loaded before component stylesheets to ensure variables, utilities and shared layout rules are available throughout the application. 

<!-- Core Framework -->
<link rel="stylesheet" href="css/reset.css">
<link rel="stylesheet" href="css/variables.css">
<link rel="stylesheet" href="css/typography.css">
<link rel="stylesheet" href="css/layout.css">
<link rel="stylesheet" href="css/utilities.css">
<link rel="stylesheet" href="css/animations.css">

<!-- Components -->
<link rel="stylesheet" href="css/components/navbar.css">
<link rel="stylesheet" href="css/components/buttons.css">
<link rel="stylesheet" href="css/components/cards.css">
<link rel="stylesheet" href="css/components/forms.css">
<link rel="stylesheet" href="css/components/footer.css">

<!-- Documentation (Optional) -->
<link rel="stylesheet" href="css/showcase.css">

Load Core Files First

Reset, variables, typography, layout and utilities provide the foundation used by every component stylesheet in the framework.

Components Depend on the Framework

Component styles assume that the framework variables and layout system have already been loaded.

JavaScript Installation

Load JavaScript After HTML

JavaScript modules should be loaded after the page content has been rendered. This improves perceived performance and ensures all interactive components can locate the required HTML elements. 

<script type="module" src="js/app.js"></script>
<script type="module" src="js/navbar.js"></script>
<script type="module" src="js/sidebar.js"></script>
<script type="module" src="js/tabs.js"></script>
<script type="module" src="js/dropdown.js"></script>
<script type="module" src="js/modal.js"></script>
<script type="module" src="js/theme.js"></script>
<script type="module" src="js/playground.js"></script>
<script type="module" src="js/search.js"></script>
<script type="module" src="js/animations.js"></script>
<script type="module" src="js/toast.js"></script>

Module Architecture

Every JavaScript file is responsible for a single feature, making the framework easier to maintain and extend over time.

Load Scripts Last

Loading scripts after the document prevents render blocking and allows each module to initialize successfully.

Verification

Confirm the Framework is Working

Complete the following checklist to verify that ASLDS has been installed correctly before beginning development.

  1. Confirm CSS variables load successfully.
  2. Verify typography matches the documentation website.
  3. Ensure primary and secondary buttons display correctly.
  4. Confirm the navigation bar renders properly.
  5. Check that cards use the expected spacing and elevation.
  6. Resize the browser to verify the responsive layout.
  7. Confirm JavaScript modules initialize without browser console errors.
  8. Verify light and dark theme functionality where applicable.
Troubleshooting

Resolve Common Installation Issues

The following guidance addresses the most common installation problems encountered when integrating the ASL Design System into a project.

CSS Not Loading

Verify that every stylesheet path is correct and that all framework files are available inside the expected directory.

Incorrect File Paths

Ensure all relative paths correctly reference the CSS, JavaScript and asset folders from the current page.

Missing Components

Confirm the required component stylesheet has been imported before using its HTML structure.

Wrong Stylesheet Order

Load the core framework before any component stylesheet to preserve the correct dependency order.

Browser Cache

Perform a hard refresh or clear the browser cache after updating framework files.

Responsive Problems

Confirm the viewport meta tag is present and that all required layout files are loaded correctly.

Engineering Workflow

Recommended Development Workflow

Following a consistent engineering workflow ensures long-term maintainability, predictable upgrades and a unified user experience across every A Square L application.

Protect Framework Files

Keep the ASLDS framework unchanged and apply project-specific customizations in separate files.

Extend, Don't Replace

Build upon existing components instead of rewriting framework functionality.

Accessibility First

Maintain semantic HTML, keyboard navigation and accessible interface patterns throughout every project.

Reuse Components

Use existing ASLDS components before creating custom alternatives.

Naming Consistency

Follow the official ASLDS CSS API and avoid introducing conflicting framework class names.

Frequently Asked Questions

Installation FAQ

Can I modify ASLDS?

Direct modification is not recommended. Extend the framework through project-specific files.

Can unused files be removed?

Yes, provided dependencies between components are understood and preserved.

Does ASLDS support dark mode?

Yes. Theme switching is handled by the framework JavaScript modules and design tokens.

Can I use ASLDS without JavaScript?

Most layout and visual components work without JavaScript, while interactive components require the corresponding modules.

How do I update?

Replace framework files with the latest stable release while keeping project-specific customizations separate.
