Foundation

Color Foundation

Every visual experience inside ASLDS is built on a carefully designed color system.

The Color Foundation defines the design tokens, semantic colors and accessibility principles that create a consistent, recognizable and scalable visual language throughout every A Square L Innovate application.

Overview

Introduction

Colors communicate hierarchy, interaction, meaning and brand identity. ASLDS uses semantic design tokens instead of hard-coded values to ensure consistency, maintainability and theme flexibility.

Philosophy

Color Philosophy

Consistency

Every component references design tokens instead of raw color values.

Accessibility

Color combinations are selected to maximize readability and meet WCAG contrast recommendations.

Scalability

Centralized variables allow themes and future design updates without rewriting components.

Principles

Design Principles

Purpose First

Every color has a defined semantic purpose rather than being purely decorative.

Minimal Palette

Reduce unnecessary colors to create a stronger visual identity.

Theme Ready

Tokens support future light and dark theme expansion.

Accessibility

WCAG Contrast Guidelines

High Contrast

Primary text and controls should meet recommended WCAG contrast ratios.

Avoid Low Contrast

Decorative combinations should never reduce content readability.

Guidelines

Color Do's & Don'ts

✓ Do

  • Use semantic tokens.
  • Maintain accessibility.
  • Keep branding consistent.

✕ Don't

  • Hard-code colors.
  • Mix unrelated palettes.
  • Ignore contrast ratios.

Best Practices

Recommended Usage

  • ✓ Use semantic design tokens.
  • ✓ Maintain sufficient contrast.
  • ✓ Keep branding consistent.
  • ✓ Reuse framework variables.
  • ✓ Avoid hard-coded colors.
  • ✓ Test both desktop and mobile.
Mistakes

Common Mistakes

Avoid replacing framework variables with hard-coded values or introducing inconsistent colors into reusable components.
FAQ

Frequently Asked Questions

Can I create custom colors?

Yes. Extend ASLDS using your own project-specific variables rather than modifying the framework.

Should I edit variables.css?

No. Keep framework files unchanged and override values only within your application when necessary.
