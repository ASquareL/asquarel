Foundation

Shadows

Elevation creates hierarchy, focus and depth while preserving clarity and accessibility across every ASLDS interface.

The ASL Design System shadow foundation provides a consistent elevation scale for surfaces, cards, overlays, menus, navigation and dialogs. Every shadow is implemented through reusable design tokens, ensuring visual consistency across applications and themes.

Introduction

Elevation & Visual Hierarchy

Shadows communicate depth without relying on heavy borders or unnecessary decoration. They help users identify interactive elements, understand interface hierarchy and distinguish floating surfaces from the page background. ASLDS uses a carefully balanced elevation scale to keep interfaces clean, accessible and visually consistent.

Visual Hierarchy

Elevation helps users understand which components deserve immediate attention.

Accessibility

Shadows complement contrast instead of replacing it, ensuring interfaces remain understandable for all users.

Consistency

Every elevation level is defined by reusable design tokens shared across the framework.

Usage

Elevation Guidelines

Choose the lowest elevation that clearly communicates hierarchy. Excessive shadows reduce clarity and create unnecessary visual noise.

Background Surfaces

Usually use no shadow or the smallest available elevation.

Cards

Medium shadows separate grouped content from surrounding layouts.

Dropdowns

Larger elevation helps floating menus remain distinguishable.

Navigation

Sticky navigation benefits from subtle elevation to remain visible.

Floating Panels

Floating utility panels should appear clearly above surrounding content.

Dialogs & Modals

Highest elevation level reserved for important modal interactions.

Theme Support

Light & Dark Mode

ASLDS shadow tokens automatically complement both light and dark themes. Shadows remain subtle while preserving sufficient separation between surfaces in every interface.

Light Theme

Uses softer shadows to create natural depth against bright backgrounds.

Dark Theme

Combines reduced opacity with subtle highlights to preserve visual hierarchy without excessive contrast.

Guidance

Best Practices

Do

  • Use official shadow tokens.
  • Increase elevation gradually.
  • Combine shadows with spacing.
  • Keep hierarchy consistent.

Don't

  • Create arbitrary shadows.
  • Stack multiple shadows excessively.
  • Replace contrast with shadows.
  • Overuse colored elevation.

Accessibility

Shadows should reinforce visual hierarchy but never become the only indicator of interaction or focus.

Performance

Prefer reusable design tokens instead of large custom shadow definitions to keep rendering efficient.

Developer Usage

Using Shadow Tokens

Always reference the official ASLDS shadow variables instead of defining custom box-shadow values. This guarantees visual consistency across every application.

HTML Example 

<article class="card">

    ...

</article>

CSS Variable 

.card{

    box-shadow:var(--shadow-md);

}
