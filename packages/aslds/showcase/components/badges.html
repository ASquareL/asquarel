Badges

Overview

Badge Overview

Badges communicate compact pieces of information, such as labels, notification counts, categories, statuses and priorities. They are designed to be lightweight, recognizable and accessible.

Compact

Display important information without occupying significant interface space.

Consistent

Reuse semantic badge styles throughout the entire product ecosystem.

Informative

Provide meaningful visual context while avoiding unnecessary complexity.

Anatomy

Badge Anatomy

Every ASLDS badge follows a simple, reusable structure that ensures clarity, scalability and consistent visual communication across every application.

Container

The outer badge element provides the overall shape, spacing and semantic color.

Label

Displays concise text describing status, category or priority.

Semantic Color

Colors communicate meaning without replacing descriptive text.

Optional Icon

Icons may reinforce meaning when paired with readable labels.

Notification Count

Numeric badges communicate unread items, pending tasks or notification totals.

Accessibility

Accessibility Guidelines

Badge content should always remain understandable without relying exclusively on color or visual styling.

Meaningful Labels

Every badge should communicate meaningful information through readable text.

Color Independence

Semantic colors should reinforce meaning, never replace descriptive content.

Contrast

Ensure sufficient contrast between badge text and background in every theme.

Best Practices

Do & Don't

Do

  • Keep badge labels short.
  • Use semantic colors consistently.
  • Display only meaningful information.
  • Maintain readable contrast.
  • Reuse standard badge variants.

Don't

  • Use badges for long text.
  • Depend only on color.
  • Overload interfaces with badges.
  • Use inconsistent semantic meanings.
  • Create unnecessary badge variations.
