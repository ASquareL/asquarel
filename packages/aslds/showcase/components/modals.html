Overview

Modal Overview

Modal dialogs temporarily interrupt user workflows to present critical information, request decisions or complete focused tasks without leaving the current page.

Focused

Direct user attention toward a single task or decision.

Reusable

Standard dialog layouts ensure consistency across every ASLDS application.

Accessible

Built with semantic dialog structure, keyboard support and focus management.

Anatomy

Modal Anatomy

Every ASLDS modal follows a consistent structure that promotes usability, accessibility and predictable interaction throughout the design system.

Overlay

Prevents interaction with background content while directing attention toward the dialog.

Dialog Container

Holds all modal content inside a structured and visually separated panel.

Header

Displays the dialog title and optional close action.

Body

Contains forms, messages, previews or any interactive content.

Footer

Contains the primary and secondary action buttons.

Accessibility

Accessibility Guidelines

Modal dialogs should maintain focus management, semantic structure and complete keyboard accessibility.

Keyboard Navigation

Users should be able to open, navigate and close modal dialogs using only the keyboard.

Focus Management

Move keyboard focus into the dialog when it opens and restore focus to the triggering element when it closes.

ARIA Support

Use semantic dialog roles together with descriptive labels and accessible relationships for assistive technologies.

Escape Key

Support closing non-destructive dialogs using the Escape key whenever appropriate.

Best Practices

Do & Don't

Do

  • Keep dialogs focused on one task.
  • Provide clear titles.
  • Offer obvious primary actions.
  • Support keyboard navigation.
  • Close dialogs predictably.

Don't

  • Stack multiple dialogs.
  • Hide critical actions.
  • Trap keyboard users.
  • Interrupt users unnecessarily.
  • Display excessive content.
