Overview

Button Component

Buttons initiate user actions throughout the ASL Design System. They communicate hierarchy through color, emphasis and placement while maintaining a consistent interaction pattern across every product.

Primary Actions

Use one primary button for the most important action in a view.

Secondary Actions

Secondary buttons support alternative actions without competing with the primary call to action.

Accessibility

Buttons remain keyboard accessible, maintain visible focus and provide sufficient color contrast.

Variants

Button Variants

Choose the appropriate button style according to the visual importance of the action.

Primary

Highest emphasis action. 

<button class="btn btn-primary">Primary</button>

Secondary

Supporting actions. 

<button class="btn btn-secondary">Secondary</button>

Outline

Medium emphasis. 

<button class="btn btn-outline">Outline</button>

Ghost

Low emphasis actions displayed on minimal surfaces. 

<button class="btn btn-ghost">Ghost</button>

Text

Lightweight actions placed inline with surrounding content. 

<button class="btn btn-text">Text</button>

Link

Navigation or contextual actions that appear similar to hyperlinks. 

<button class="btn btn-link">Link</button>

Success

Indicates successful or positive actions. 

<button class="btn btn-success">Success</button>

Warning

Used for actions requiring additional user attention. 

<button class="btn btn-warning">Warning</button>

Danger

Reserved for destructive or irreversible actions. 

<button class="btn btn-danger">Danger</button>

Info

Highlights informational actions or secondary workflows. 

<button class="btn btn-info">Info</button>

Accessibility

Accessible Button Design

Buttons should remain usable for every user, regardless of device, assistive technology or interaction method.

Keyboard Navigation

Every button must be reachable using the Tab key and activated using Enter or Space.

Focus Visibility

Preserve the default ASLDS focus indicator to ensure keyboard users can easily identify the active control.

Touch Targets

Ensure interactive controls remain large enough for touch interaction on mobile devices.

Screen Readers

Provide descriptive labels for icon-only buttons using accessible names such as aria-label.

Color Contrast

Never rely solely on color to communicate meaning. Maintain sufficient contrast across every button variant.

Reduced Motion

Respect reduced-motion preferences and avoid unnecessary animation during interaction.

Best Practices

Do & Don't

Do

  • Use one primary button per section.
  • Keep labels concise and action-oriented.
  • Maintain consistent spacing.
  • Use semantic button variants.
  • Align grouped actions consistently.
  • Provide visible focus indicators.
  • Use icons to reinforce labels.
  • Disable buttons only when necessary.

Don't

  • Place multiple primary buttons together.
  • Use vague labels such as "Click Here".
  • Depend only on color for meaning.
  • Mix unrelated button styles.
  • Remove keyboard focus styles.
  • Use destructive colors unnecessarily.
  • Overcrowd toolbars with actions.
  • Create inconsistent sizing.
