Anatomy

Table Anatomy

Every ASLDS table is built from predictable, semantic elements that improve readability, accessibility and scalability across enterprise applications.

Table Wrapper

Provides responsive horizontal scrolling on smaller devices while preserving layout.

Header

Defines column labels and communicates the structure of the dataset.

Body

Displays records using consistent row and column alignment.

Rows

Each row represents an individual record within the dataset.

Cells

Cells contain structured values that remain aligned across every column.

Responsive

Responsive Tables

Wrap tables inside the standard table wrapper to enable horizontal scrolling on smaller screens without breaking the layout.

Mobile Friendly

The table-wrapper keeps large datasets usable across all screen sizes.

Enterprise Ready

Designed for dashboards, reports, administration panels and analytics interfaces.

Accessibility

Accessibility Guidelines

Build semantic tables that remain understandable for every user and assistive technology.

Semantic Structure

Always use semantic table elements such as caption, thead, tbody, tr, th and td to provide meaningful document structure.

Header Cells

Identify column headers using <th> elements with the appropriate scope attributes whenever applicable.

Responsive Layout

Wrap large tables inside a table-wrapper container to preserve usability on smaller devices.

Readability

Keep column titles concise, align related values consistently and avoid overcrowding large datasets.

Best Practices

Do & Don't

Do

  • Use descriptive column headings.
  • Keep rows consistently aligned.
  • Support responsive layouts.
  • Use semantic HTML elements.
  • Display related information together.

Don't

  • Overcrowd tables with unnecessary data.
  • Use tables for page layout.
  • Hide important headers.
  • Break responsive behavior.
  • Use inconsistent alignment.
