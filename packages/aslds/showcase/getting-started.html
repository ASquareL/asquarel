Before You Begin

Prerequisites

Before integrating ASLDS into your project, ensure your development environment and knowledge meet these basic requirements.

HTML5 Knowledge

Understand semantic HTML structure and accessibility fundamentals.

CSS Fundamentals

Familiarity with selectors, layouts, variables and responsive design concepts.

JavaScript Basics

Basic knowledge of modern JavaScript and ES Modules.

Modern Browser

Use the latest version of Chrome, Edge, Firefox or Safari for development.

Installation

Choose Your Installation Method

ASLDS currently supports manual installation for maximum control and transparency. Additional installation methods are planned for future releases.

Recommended

Manual Installation

Download the ASL Design System package, copy the required CSS and JavaScript folders into your project, and reference them using the recommended loading order.

Available

Git Clone

Clone the official repository to obtain the latest development version and track future updates using Git.

Coming Soon

NPM Package

Install ASLDS directly into your project using npm with automatic version management and dependency updates.

Coming Soon

CDN Delivery

Quickly prototype applications by loading ASLDS assets from a globally distributed content delivery network.

Project Structure

Recommended Folder Structure

Organizing your project consistently improves maintainability, scalability and collaboration across engineering teams. 

project/
│
├── css/
├── js/
├── assets/
│
├── showcase/
│
├── foundations/
│
└── components/

css/

Contains the complete ASLDS framework, component styles and design tokens.

js/

Contains reusable JavaScript modules responsible for interactive components.

assets/

Store project images, icons, fonts, videos and other static resources.

showcase/

Documentation website demonstrating every feature of the ASL Design System.

foundations/

Documentation covering colors, typography, spacing, layout, borders and animations.

components/

Individual documentation pages for every reusable UI component available in ASLDS.

CSS Setup

Include the Framework Stylesheets

Load the framework stylesheets in the recommended order to ensure design tokens, utilities and components are available throughout your application. 

<!-- Core -->
<link rel="stylesheet" href="css/reset.css">
<link rel="stylesheet" href="css/variables.css">
<link rel="stylesheet" href="css/typography.css">
<link rel="stylesheet" href="css/layout.css">
<link rel="stylesheet" href="css/utilities.css">
<link rel="stylesheet" href="css/animations.css">

<!-- Components -->
<link rel="stylesheet" href="css/components/navbar.css">
<link rel="stylesheet" href="css/components/buttons.css">
<link rel="stylesheet" href="css/components/cards.css">
<link rel="stylesheet" href="css/components/forms.css">
<link rel="stylesheet" href="css/components/footer.css">

Why Order Matters

Core framework files define the design tokens, layout system and utilities required by every component stylesheet.

Components Last

Component styles should be loaded after the framework so they inherit shared variables and utilities.

JavaScript Setup

Load JavaScript Modules

Import JavaScript modules after the page content to improve loading performance and ensure all HTML elements are available. 

<script type="module" src="js/app.js"></script>
<script type="module" src="js/navbar.js"></script>
<script type="module" src="js/sidebar.js"></script>
<script type="module" src="js/tabs.js"></script>
<script type="module" src="js/dropdown.js"></script>
<script type="module" src="js/modal.js"></script>
<script type="module" src="js/theme.js"></script>
<script type="module" src="js/playground.js"></script>
<script type="module" src="js/search.js"></script>
<script type="module" src="js/animations.js"></script>
<script type="module" src="js/toast.js"></script>

Recommended Placement

Load JavaScript immediately before the closing </body> tag to avoid blocking page rendering.

ES Modules

Each module has a single responsibility, making the framework easier to maintain and extend.

First Project

Build Your First ASLDS Page

The following template demonstrates the minimum structure required to begin building an application with the ASL Design System. 

<!DOCTYPE html>
<html lang="en">

<head>

    <meta charset="UTF-8">

    <meta
        name="viewport"
        content="width=device-width, initial-scale=1.0"
    >

    <title>My ASLDS Project</title>

    <link rel="stylesheet" href="css/reset.css">
    <link rel="stylesheet" href="css/variables.css">
    <link rel="stylesheet" href="css/layout.css">
    <link rel="stylesheet" href="css/components/buttons.css">

</head>

<body>

    <button class="btn btn-primary">

        Hello ASLDS

    </button>

</body>

</html>
Verification

Verify Your Installation

Use the following checklist to confirm that the ASL Design System has been installed and configured correctly before beginning development.

  • ✓ Typography styles load correctly.
  • ✓ Theme variables are available.
  • ✓ Buttons use ASLDS styling.
  • ✓ Navbar renders correctly.
  • ✓ Cards display proper spacing.
  • ✓ Responsive layouts work on all devices.
  • ✓ JavaScript modules load without errors.
  • ✓ Design tokens are applied consistently.
Engineering

Best Practices

Following these recommendations ensures your applications remain scalable, maintainable and consistent with the ASL Design System.

Preserve Framework Integrity

Avoid editing framework files directly. Keep upgrades simple by placing project-specific styles in separate files.

Reuse Components

Build interfaces using the existing ASLDS component library instead of recreating similar UI elements.

Follow Naming Standards

Use the official ASLDS CSS API and avoid introducing custom framework class names.

Accessibility First

Build semantic, keyboard-accessible interfaces that comply with WCAG recommendations.

Separate Custom Styles

Extend the framework without modifying it. Keep custom project styling isolated from ASLDS.
