Lesson 1.3: Cryptography & Security

Duration: 55 minutes | Difficulty: Intermediate

The Foundations of Blockchain Security

Blockchain security relies on cryptographic techniques developed over decades. Understanding these fundamentals is crucial for grasping how blockchain ensures data integrity and authenticity.

Cryptography: The practice of secure communication in the presence of an adversary. It's the mathematical foundation that makes blockchain possible.

Hash Functions

A hash function is a mathematical algorithm that converts input data of any size into a fixed-size output (hash). Hash functions are fundamental to blockchain security.

Properties of Cryptographic Hash Functions

  • Deterministic: Same input always produces same output
  • Fast: Quick to compute for any input
  • Avalanche Effect: Tiny change in input drastically changes output
  • One-Way: Impossible to reverse (find input from output)
  • Collision-Resistant: Nearly impossible to find two inputs with same hash
  • Fixed Output: Always produces same length output
Example: SHA-256 (used by Bitcoin) takes any input and produces a 256-bit (64 hex character) output. Changing one letter in input completely changes the hash.

Hash Functions in Blockchain

  • Block hashes identify blocks uniquely
  • Linking blocks: Each block contains previous block's hash
  • Transaction verification: Transactions are hashed
  • Merkle trees: Efficient verification of large datasets

Public-Key Cryptography

Public-key cryptography (asymmetric cryptography) uses two related keys: a public key (anyone can see) and a private key (only you know). This enables digital signatures and secure communication.

How Public-Key Cryptography Works

  1. Generate a key pair (public + private key)
  2. Share your public key with others
  3. Others can encrypt messages with your public key
  4. Only you can decrypt with your private key
  5. You can sign messages with your private key
  6. Others verify with your public key
The Magic: It's mathematically easy to compute public key from private key, but practically impossible to reverse.

Elliptic Curve Cryptography (ECC)

Bitcoin and Ethereum use ECDSA (Elliptic Curve Digital Signature Algorithm), which uses elliptic curve mathematics. It provides the same security as RSA with smaller key sizes.

  • Bitcoin: Uses secp256k1 curve
  • Ethereum: Also uses secp256k1 curve
  • Advantage: 256-bit keys provide security equivalent to 3072-bit RSA keys

Digital Signatures

A digital signature proves you authorized a transaction without revealing your private key. It's the cryptographic equivalent of a handwritten signature but mathematically secure.

Creating a Digital Signature

  1. Create a transaction
  2. Hash the transaction data
  3. Sign the hash with your private key
  4. Create a signature (unique to this transaction + your key)
  5. Include signature with the transaction

Verifying a Digital Signature

  1. Receive a transaction with signature
  2. Hash the transaction data
  3. Use sender's public key to verify the signature
  4. If valid, the transaction is authentic
Non-Repudiation: Once you sign a transaction, you cannot claim you didn't sign it. The signature proves you authorized it.

Merkle Trees

A Merkle tree is a data structure that efficiently summarizes large datasets. Each block in a blockchain contains a Merkle root (hash of all transactions).

How Merkle Trees Work

  1. Transactions are the "leaves" of the tree
  2. Adjacent leaves are hashed together to create "parent" nodes
  3. Parents are hashed together to create higher levels
  4. Continue until one hash remains: the Merkle root

Advantages of Merkle Trees

  • Efficient: Verify transaction inclusion without storing entire tree
  • Compact: Single root hash represents all transactions
  • Secure: Any change to a transaction changes the root
  • Fast verification: Logarithmic time to verify a transaction

Key Management & Security

Private Key Security

Critical: If someone gains access to your private key, they can take all your funds. There is no recovery mechanism.
  • Never share: Your private key is like your password and bank account combined
  • Secure storage: Use hardware wallets for large amounts
  • Backups: Keep encrypted backups, preferably offline
  • Seed phrases: Backup recovery phrases are critical

Address Derivation

Your blockchain address (like Bitcoin or Ethereum address) is derived from your public key:

  • Private Key → Public Key (using elliptic curve math)
  • Public Key → Address (using hash functions)
  • Address is public but derived from private key

Cryptographic Attacks & Protections

Common Attacks

  • 51% Attack: Majority of network power performs double-spend; mitigated by distributed mining
  • Phishing: Tricking users to reveal private keys; protection: awareness and hardware wallets
  • Sybil Attack: Creating many fake nodes; mitigation: proof-of-work/stake, reputation
  • Double-Spending: Spending same coin twice; prevented by consensus and immutability

Summary

Blockchain security rests on three cryptographic pillars:

  1. Hash Functions: Ensure data integrity and linking of blocks
  2. Public-Key Cryptography: Enable secure transactions and authentication
  3. Digital Signatures: Prove ownership and authorization
Remember: No cryptocurrency is more secure than your private key management. Technology can be secure, but user behavior is often the weakest link.
