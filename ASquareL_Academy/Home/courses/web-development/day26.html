📅 Week 9 - Day 26: Promises & Async JS

Duration: 3 hours | Focus: Non-Blocking Architecture

⏳ The Asynchronous Web

JavaScript is traditionally single-threaded, meaning it executes one line of code at a time. But in enterprise development, we cannot wait for a database to load before running the rest of our application. We need Asynchronous JavaScript to handle tasks like fetching POS terminal data or authenticating a user in the background.

1. What is a Promise?

A Promise is exactly what it sounds like: a guarantee that a process will eventually finish in the future. It has three states:

  • Pending: The task is still running (e.g., waiting for the server).
  • Fulfilled: The task succeeded, and we have the data.
  • Rejected: The task failed (e.g., the internet disconnected).
// Creating a Promise const checkTerminalStatus = new Promise((resolve, reject) => { let isOnline = true; if(isOnline) { resolve("Terminal is active and ready."); // Success! } else { reject("Connection failed."); // Error! } });

2. Consuming a Promise (.then and .catch)

Once a promise is created, we need to "consume" it. We use .then() to handle the success (resolve) and .catch() to handle the error (reject).

// Executing the Promise checkTerminalStatus .then(response => { console.log(response); // Output: Terminal is active and ready. }) .catch(error => { console.error(error); });

3. The Modern Approach: Async / Await

While .then() works perfectly, modern ES6+ gives us an even cleaner way to handle promises using async and await. It makes asynchronous code look synchronous, which is much easier to read and debug.

// ✅ THE ENTERPRISE WAY const getSystemStatus = async () => { try { // The code PAUSES here until the promise resolves const response = await checkTerminalStatus; console.log(response); } catch (error) { // If the promise rejects, it jumps directly to this catch block console.error("Alert:", error); } }; getSystemStatus();
