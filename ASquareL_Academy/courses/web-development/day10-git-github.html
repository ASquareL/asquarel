🌳 Understanding Branches

What is a Branch?

A branch is an independent line of development. It allows you to build a new feature or fix a bug in a completely safe, isolated environment without breaking the live website (the main branch).

Why Use Branches & GitHub?

  • Isolation: Develop features independently without crashing the app.
  • Collaboration: Multiple team members can work simultaneously on the same project using GitHub.
  • Code Review (Pull Requests): Peers can review your branch on GitHub before it is permanently merged to main.

Branch Visualization

main:     A---B---C-----------F---G
                   \         /
feature:            D---E---/

In this diagram, Commits D and E happen on a separate feature branch. Once tested and approved via a Pull Request on GitHub, they are merged back into main at Commit F.

🔧 Essential Git Branch Commands

Command Description
git branch List all local branches (current branch has a *)
git checkout -b branch-name Create a new branch AND immediately switch to it
git checkout branch-name Switch to an existing branch
git push -u origin branch-name Push a newly created branch up to GitHub

📝 Creating and Pushing Branches

Step 1: Create a New Branch

# The fastest, most professional way to create and switch branches
$ git checkout -b feature-dark-mode

Step 2: Work on Your Branch

# Make changes to your HTML/CSS files, then add and commit as usual
$ git add .
$ git commit -m "Added dark mode CSS variables"

Step 3: Push the Branch to GitHub

# Because this branch doesn't exist on GitHub yet, you must tell GitHub to create it
$ git push -u origin feature-dark-mode

# Future pushes on this branch will just be:
$ git push

🔀 Merging via GitHub Pull Requests

In professional teams, you rarely merge code in your terminal. Instead, you push your branch to GitHub and open a Pull Request (PR).

The Pull Request Workflow

  1. Push your branch to GitHub using git push -u origin branch-name.
  2. Go to your repository on GitHub.com.
  3. You will see a green button that says "Compare & pull request". Click it!
  4. Leave a comment explaining what your code does.
  5. Click Create pull request.
  6. Your team members will review your code. Once approved, you click Merge pull request on GitHub.
  7. Finally, go back to your VS Code terminal and pull the newly merged code:
# After merging on GitHub, update your local computer
$ git checkout main
$ git pull origin main

⚠️ Merge Conflicts

Don't Panic!

Merge conflicts happen when two developers edit the exact same line of code in the same file. Git doesn't know which version to keep, so it pauses the merge and asks a human (you) to decide.

What a Conflict Looks Like in VS Code

If you open the conflicted file, Git will have injected markers into your code:

/* style.css */
button {
padding: 10px 20px;
<<<<<<< HEAD
background: #D4AF37; /* The code currently on main */
=======
background: #10b981; /* The code coming from your branch */
>>>>>>> feature-branch
border: none;
}

How to Resolve It

  1. Open the conflicted file in VS Code.
  2. Look for the <<<<<<< markers.
  3. Delete the markers and delete the version of the code you DO NOT want. Keep the code you DO want.
  4. Save the file.
  5. Run git add . and git commit -m "Resolved merge conflict".

🔄 The Professional Team Workflow

  • DO: Create a new branch for every single new feature or bug fix.
  • DO: Use GitHub Pull Requests to merge code so there is a paper trail of changes.
  • DON'T: Commit directly to the `main` branch. Main should only be updated via GitHub merges.

💻 Main Activity: GitHub PR Practice

Task 1: The Pull Request

  1. Make sure you are on main: git checkout main
  2. Create a new branch: git checkout -b feature-contact-button
  3. Add a new button to your HTML file.
  4. Commit the code: git add . then git commit -m "Added contact button"
  5. Push to GitHub: git push -u origin feature-contact-button
  6. Go to GitHub.com, create a Pull Request, and merge it!
  7. Return to VS Code: git checkout main -> git pull origin main.

Task 2: Force a Conflict

Let's intentionally cause a conflict locally so you learn how to fix it.

  1. On main, change the background color of your website to `#111`. Commit it.
  2. Create a branch: git checkout -b rogue-branch
  3. Change the background color of the SAME line of code to `red`. Commit it.
  4. Switch back to main: git checkout main
  5. Change the background color of the SAME line of code to `blue`. Commit it.
  6. Try to merge: git merge rogue-branch. BOOM! Conflict.
  7. Open the file, delete the markers, pick your favorite color, save, add, and commit!
