Lesson 1.4: Blocks, Transactions & Mining

Duration: 60 minutes | Difficulty: Intermediate

Understanding Blocks

A block is a collection of transactions and metadata that is added to the blockchain. Each block references the previous block, creating an immutable chain.

Block Structure

Each block contains:

  • Block Header: Metadata about the block
  • Transactions: The actual data (cryptocurrency transfers)

Block Header Components (Bitcoin)

  • Version: Software version that created the block
  • Previous Block Hash: Hash of the preceding block (links the chain)
  • Merkle Root: Hash of all transactions in the block
  • Timestamp: When the block was created (Unix timestamp)
  • Difficulty Target: Mining difficulty for this block
  • Nonce: Number used once (miners change this to find valid hash)
Block Hash: Created by hashing the entire block header. Changing any part of the header changes the hash, making the block invalid.

Understanding Transactions

A transaction is a transfer of value from one address to another. All transactions in a block are validated and included in the Merkle tree.

Transaction Anatomy

  • Input: Source of the funds (previous transaction output)
  • Output: Destination address and amount
  • Digital Signature: Proves the sender authorized the transaction
  • Transaction Fee: Incentive for miners to include the transaction

UTXO Model (Bitcoin)

Bitcoin uses the Unspent Transaction Output (UTXO) model:

  • Every transaction has inputs and outputs
  • Inputs are outputs from previous transactions
  • When you spend a UTXO, it becomes consumed
  • To spend Bitcoin, you must reference a UTXO you own
  • You can only spend if you can provide the private key signature
Change Address: If you send 5 BTC but only own a 10 BTC UTXO, the transaction creates two outputs: 5 to recipient and 5 back to you (change).

Account Model (Ethereum)

Ethereum uses a different model:

  • Each address has a balance tracked directly
  • Simpler to understand and work with
  • Enables smart contract functionality
  • More state data to maintain

The Mining Process

Mining is the process of validating transactions and creating new blocks. Miners compete to solve a computational puzzle to earn rewards.

Mining Steps (Proof of Work)

  1. Miners collect pending transactions into a mempool
  2. Select transactions and create a candidate block
  3. Create the block header with all the metadata
  4. Hash the block header repeatedly with different nonce values
  5. First miner to find a hash below the target broadcasts the block
  6. Other nodes verify the block is valid
  7. Block is accepted and added to the chain
  8. Miner receives block reward + transaction fees

Mining Difficulty

The network adjusts difficulty to maintain consistent block times:

  • Bitcoin: ~10 minute block time
  • Ethereum (PoW era): ~12-14 second block time
  • Difficulty adjusts every 2 weeks (Bitcoin) or every block (Ethereum)
  • More miners = higher difficulty to maintain consistent timing
Difficulty Adjustment: If blocks are being created too fast, difficulty increases. If too slow, it decreases. This maintains network security while keeping consistent block times.

Mining Rewards

Miners are incentivized to participate through two sources of income:

Block Reward

  • Fresh Bitcoin created with each block (Coinbase transaction)
  • Bitcoin: Started at 50 BTC, halves every 210,000 blocks (~4 years)
  • Currently: 6.25 BTC per block
  • Scheduled to reach 0 around 2140

Transaction Fees

  • Difference between inputs and outputs
  • User sets fee (usually in satoshis per byte)
  • Higher fee = higher priority
  • Miners prioritize high-fee transactions

Mining Pools & Centralization

Individual mining is often unprofitable, so miners join pools:

  • Pool coordinator collects miners' hashpower
  • Block reward is distributed among pool members
  • Reduces variance but increases centralization risk
  • Major pools can influence protocol changes

Mempool & Transaction Confirmation

Before transactions are mined into a block, they sit in the mempool:

  • Mempool: Memory pool of unconfirmed transactions
  • Confirmation: Transaction included in a block
  • Block Confirmations: Number of blocks mined after your transaction
  • More confirmations = more finality

Transaction Fee Market

  • When network is congested, fees increase
  • Users compete by offering higher fees
  • Miners prioritize high-fee transactions
  • Fee estimation tools help users choose appropriate fees

51% Attack Scenario

Mining creates security against 51% attacks:

  • To rewrite history, attacker needs >50% of network hashpower
  • Cost of attacking Bitcoin is extremely high
  • Attacking smaller networks is easier but still expensive
  • Economic incentives make honest participation more profitable
Security from Proof of Work: The more hashpower securing the network, the more expensive an attack becomes. This economic security is blockchain's greatest strength.
